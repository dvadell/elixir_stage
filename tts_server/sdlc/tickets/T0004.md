----
title: Kubernetes deployment (manifests, probes, resources, model-cache volume)
----

Deploy the TTS server as its **own pod**: Deployment + internal ClusterIP
Service, correct liveness/readiness probes, conservative resource requests, a
rollout strategy that tolerates a single replica, and a persistent model cache
volume so restarts are fast. Consumed by `soundai` via in-cluster DNS.

## Desired architecture

```text
┌───────────────────────────────────────────────────────┐
│ cluster                                               │
│   tts-server Deployment (replicas: 1)                 │
│     container: tts-server (image, port 8080)          │
│       liveness:  GET /healthz   period 10s, failure 6 │
│       readiness: GET /readyz    period 5s,  initialDelay 5s, failure 30 │
│       resources: req cpu 250m / mem 384Mi             │
│                  lim cpu 1    / mem 768Mi             │
│       volume: model-cache PVC -> TTS_CACHE_DIR        │
│   tts-server Service (ClusterIP, 8080)                │
│     DNS: http://tts-server:<namespace>.svc...:8080    │
└───────────────────────────────────────────────────────┘
```

## Scope

### 1. Manifests

- `deploy/deployment.yaml`:
  - `replicas: 1` (serialized synthesis; scale later with the T0003c
    worker_threads note). `strategy: RollingUpdate` with `maxUnavailable: 0` so
    the single replica is never briefly offline.
  - Probes (per `TECHNICAL_NOTES.md` §6):
    - `livenessProbe` → `GET /healthz`, `periodSeconds: 10`,
      `failureThreshold: 6` (liveness must not depend on the model).
    - `readinessProbe` → `GET /readyz`, `periodSeconds: 5`,
      `initialDelaySeconds: 5`, `failureThreshold: 30` (a cold start that
      downloads the model takes tens of seconds; the readiness probe must not
      crash-loop the pod while it warms).
  - Resources: `requests {cpu: 250m, memory: 384Mi}`,
    `limits {cpu: 1, memory: 768Mi}` (tuned after T0005's memory benchmark).
  - `terminationGracePeriodSeconds: 30` (>= drain budget in T0003b).
  - Env from the `TECHNICAL_NOTES.md` §5 table; `TTS_CACHE_DIR` points at the
    mounted volume.
  - Model cache: mount a `PersistentVolumeClaim` at the cache path (default
    provider StorageClass). Document the "bake the model into the image"
    alternative as a tradeoff (faster start vs bigger image).
- `deploy/service.yaml`: `ClusterIP` only, port/targetPort 8080. No
  `NodePort`/`LoadBalancer`/Ingress — the service is internal.
- (Optional, operator preference) a `NetworkPolicy` restricting ingress to the
  `soundai` app's namespace/labels.

### 2. soundai consumer wiring (contract, not code)

- Document in `TECHNICAL_NOTES.md` §7 the `SOUNDAI_TTS_URL` for the Phoenix app,
  e.g. `http://tts-server.<namespace>.svc.cluster.local:8080`. The actual
  `soundai` proxy endpoint (`POST /api/tts` + the browser `server` TTS engine +
  `/settings` option) is a separate `soundai` ticket and is **not** part of this
  project.

### 3. Rollout / ops notes

- Rolling restart re-downloads nothing when the PVC is mounted (fast ready).
- On OOM (limit exceeded), k8s restarts the pod; readiness re-gates on model
  load; PVC keeps the model cached.
- No secrets required anywhere.

## Acceptance criteria

- [ ] `kubectl apply -f deploy/` creates the Deployment and Service; the pod
      becomes Ready.
- [ ] `curl http://tts-server.<ns>:8080/v1/tts` works from a `soundai` pod (or
      a debug pod in the same namespace).
- [ ] Readiness goes 503 → 200 as the model loads; liveness stays 200 throughout.
- [ ] Pod restart after a warm cache does not re-download the model (ready in
      seconds, not minutes).
- [ ] The Service is ClusterIP-only (no external exposure).
- [ ] Resource requests/limits match the T0005-tuned numbers (updated here).

## Verification

- `kubectl apply -k deploy/` (or `-f`) and `kubectl get pods -w`; watch
  readiness flip.
- `kubectl exec` into a debug pod and `curl` the service DNS for a WAV.
- `kubectl delete pod <tts-pod>` (force recycle) → verify fast restart + Ready.
- Review probe timings against a cold start with empty cache (download included).
- From the umbrella root, `mix precommit` (no Phoenix changes expected).
