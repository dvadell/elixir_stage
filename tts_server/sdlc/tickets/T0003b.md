----
title: Graceful shutdown (drain in-flight + queued synthesis on SIGTERM)
----

Make the process recycle-friendly: on `SIGTERM`/`SIGINT`, stop accepting new
requests, finish in-flight **and queued** synthesis (drain), then exit 0. Adds
`TTS_SHUTDOWN_TIMEOUT_MS` as a hard deadline so a stuck drain can't block a k8s
kill. Depends on `Queue.drain()` implemented in T0003a; the k8s
`terminationGracePeriodSeconds` (T0004) must exceed the drain budget.

## Desired architecture

```text
SIGTERM -> stop accepting -> drain queue (in-flight + queued) -> exit 0
                                `-- TTS_SHUTDOWN_TIMEOUT_MS -> force exit 1
```

## Scope

### 1. Drain (`src/queue.mjs`)

- Implement `Queue.drain()`: resolves when in-flight + queued jobs finish.
  New `enqueue` after shutdown begins is rejected (503 or connection refused —
  the server has already stopped accepting).
- Job rejection mid-drain is explicit: a timed-out or abandoned job logs and the
  drain continues.

### 2. Shutdown path (`src/server.mjs`)

- On `SIGTERM`/`SIGINT`: flip a `shuttingDown` flag, `server.close()` (stop
  accepting new connections), then `await queue.drain()` and `process.exit(0)`.
- Hard deadline `TTS_SHUTDOWN_TIMEOUT_MS` (default 20 s): if draining overruns
  it, force-exit (currently a hardcoded 10 s timer at `server.mjs`) — make it
  config-driven.
- Replace the current bare `server.close(() => process.exit(0))` so queued work
  actually completes before exit.
- Log a drain summary: `drained {queued, inFlight, drainMs}`.

### 3. Config

- Add `TTS_SHUTDOWN_TIMEOUT_MS` to `src/config.mjs` (integer env, default
  20000, same `intEnv` pattern) and to the `TECHNICAL_NOTES.md` §5 table.
- Update the `TECHNICAL_NOTES.md` §5 note that `terminationGracePeriodSeconds`
  must be ≥ the drain budget (referenced from T0004).

## Acceptance criteria

- [ ] `SIGTERM` mid-synthesis drains in-flight + queued work and exits 0.
- [ ] Requests arriving after the signal starts are refused (no new synthesis).
- [ ] A drain that exceeds `TTS_SHUTDOWN_TIMEOUT_MS` still exits (force path).
- [ ] The drain budget is documented and `terminationGracePeriodSeconds`
      (T0004) is set to exceed it.

## Verification

- `kill -TERM <pid>` mid-synthesis (and with queued work); assert drain + exit 0.
- Run with a very small `TTS_SHUTDOWN_TIMEOUT_MS` and a stalled synthesis;
  assert the force-exit path.
- `node test/api.test.mjs`; from the umbrella root, `mix precommit`.
