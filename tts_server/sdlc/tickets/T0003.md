----
title: Robust serving (serialized queue, timeouts, graceful shutdown, model cache)
----

Make the service production-shaped: serialize synthesis through a bounded FIFO
queue (onnxruntime-web is single-threaded per session), enforce per-request
timeouts so nothing hangs, drain cleanly on SIGTERM, and persist the model cache
so restarts are fast. Also adds a `worker_threads` note for future concurrency.

## Desired architecture

```text
request -> queue (bounded, FIFO) -> synthesize (one at a time) -> respond
              |                        |-- timeout (TTS_SYNTH_TIMEOUT_MS)
              `-- queue full -> 429    `-- failure -> 500

SIGTERM -> stop accepting -> drain queue -> exit 0
```

## Scope

### 1. Serialized FIFO queue (`src/queue.mjs`)

- One synthesis in flight; the rest wait in a FIFO queue.
- Bound `TTS_MAX_QUEUE` (default 8); when full, reject the new request
  immediately with **429 `busy`** (JSON error per `PRD.md` §7) — never make a
  client wait behind an unbounded backlog.
- Each queued item carries a request id used across logs.
- Rejection/`cancel` of queued work is explicit: a timed-out synthesis logs and
  the queue moves to the next item.

### 2. Timeouts & failure isolation

- Per-synthesis timeout `TTS_SYNTH_TIMEOUT_MS` (default 30 s): on expiry, log a
  warning with request id + synth duration, return 500 `synthesis_failed` to
  that client, and continue with the next item. **A hung inference never hangs
  the service or other clients.**
- Synthesis errors are isolated per request; a crash in the pipeline wrapper
  must not take down the process (wrap and recover; the process itself only
  exits on SIGTERM).

### 3. Graceful shutdown

- On `SIGTERM`/`SIGINT`: stop accepting new connections/requests, finish
  in-flight and queued synthesis (drain), then `process.exit(0)`.
- If draining exceeds a hard deadline (e.g. `TTS_SHUTDOWN_TIMEOUT_MS`, default
  20 s), force-exit.
- K8s `terminationGracePeriodSeconds` must exceed the drain budget (see T0004).

### 4. Model cache persistence

- `env.cacheDir` is set from `TTS_CACHE_DIR` (T0002) so the cache can be mounted
  on a volume. Document (not implemented here) that the k8s Deployment mounts a
  PVC or baked-in model at that path (T0004).

### 5. Future: worker_threads pool (documented only)

- Add a note in `src/queue.mjs` describing the upgrade path to a
  `worker_threads` pool (one pipeline per worker, N = `hardwareConcurrency`,
  memory grows ~linearly) — **not implemented** in this ticket.

## Acceptance criteria

- [ ] Concurrent requests serialize correctly; audio responses are all correct
      (no interleaving/corruption).
- [ ] Exceeding `TTS_MAX_QUEUE` returns 429 `busy` promptly.
- [ ] A stalled synthesis (simulated) returns 500 after the timeout and the next
      queued request still succeeds.
- [ ] `SIGTERM` drains in-flight work and exits 0; a forced kill still exits.
- [ ] Restart with a warm `TTS_CACHE_DIR` does not re-download the model.
- [ ] Every request path terminates (200/4xx/5xx) — no hanging clients.

## Verification

- Fire N concurrent `curl`/`node:test` requests; assert all get valid WAVs and
  that logs show serialized `synthMs` (no overlap).
- Set `TTS_MAX_QUEUE=1` and saturate; assert 429 on overflow.
- Inject a fake slow synthesis (test hook) and assert the timeout path.
- `kill -TERM <pid>` mid-synthesis; assert drain + exit 0.
- From the umbrella root, `mix precommit`.
