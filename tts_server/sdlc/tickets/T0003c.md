----
title: Model cache persistence + worker_threads note (warm-cache test, docs)
----

Make restarts fast by persisting the model cache and leave a documented upgrade
path for future concurrency. The `env.cacheDir` wiring from `TTS_CACHE_DIR`
already landed in T0002 (`src/tts.mjs`); this ticket verifies it with a
warm-cache test, documents the k8s volume requirement for T0004, and adds the
`worker_threads` pool note to `src/queue.mjs` (documented only, not
implemented). Split out of the former T0003.

## Scope

### 1. Warm-cache verification

- Test that a second start with a populated `TTS_CACHE_DIR` does **not**
  re-download the model (load completes fast; no `model download` log lines).
- Confirm the cache path is honored end-to-end: set `TTS_CACHE_DIR`, cold start
  (download), warm start (no download). The cache layout is transformers.js's
  own; do not alter it.

### 2. k8s model-cache contract (docs)

- Document in `TECHNICAL_NOTES.md` §6 that the Deployment mounts a
  `PersistentVolumeClaim` (or bakes the model into the image) at the
  `TTS_CACHE_DIR` path — implemented in T0004, not here.
- EmptyDir re-downloads on every pod start (~8 s load + download) — acceptable
  during development only; note the tradeoff.

### 3. Future: worker_threads pool (documented only)

- Add a note in `src/queue.mjs` describing the upgrade path to a
  `worker_threads` pool: one pipeline per worker, N = `hardwareConcurrency`,
  memory grows ~linearly. **Not implemented** in this ticket — the note is a
  comment, not code.

## Acceptance criteria

- [ ] Restart with a warm `TTS_CACHE_DIR` does not re-download the model
      (verified by test and by absence of download logs).
- [ ] `TTS_CACHE_DIR` is honored (files land in the configured directory).
- [ ] `TECHNICAL_NOTES.md` documents the k8s volume/bake-in requirement and the
      EmptyDir tradeoff (referenced by T0004).
- [ ] `src/queue.mjs` carries the `worker_threads` upgrade note.

## Verification

- Cold start with empty `TTS_CACHE_DIR`: download logs appear. Warm restart:
  no download logs, ready in seconds.
- Inspect `TTS_CACHE_DIR` after a cold start to confirm the model landed there.
- `node test/api.test.mjs`; from the umbrella root, `mix precommit`.
