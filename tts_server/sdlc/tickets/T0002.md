----
title: Wire synthesis (model load, WAV encoding, POST /v1/tts)
----

Load `Xenova/mms-tts-spa` with `@huggingface/transformers` and implement the
real `POST /v1/tts`: validate input, synthesize on CPU/WASM, encode to WAV, and
return playable audio. This is the ticket that makes the service useful.

## Desired architecture

```text
POST /v1/tts {text, language}
   |--> validate (text present/blank/too-long, language supported)
   |--> tts.synthesize(text)            -- pipeline("text-to-speech", model)
   |        -> {audio: Float32Array, sampling_rate: 16000}
   |--> wav.encode(audio, 16000)        -- 16-bit PCM mono WAV
   |--> 200 audio/wav  (+ X-TTS-Model, X-TTS-Duration-Ms)
   |--> failures -> 422 / 500 JSON error
```

## Scope

### 1. TTS module (`src/tts.mjs`)

- Configure `env` exactly as in `TECHNICAL_NOTES.md` §2:
  `allowLocalModels=false, useBrowserCache=false, useWasmCache=false,
  logLevel="warning"`, and `cacheDir` from `TTS_CACHE_DIR` (default keeps
  transformers' own cache).
- `load()` → builds `pipeline("text-to-speech", TTS_MODEL, {device: "wasm"})`
  once; sets a `ready` flag; logs `[tts] model ready` with the model id.
  Quantized (q8) dtype is the default; expose `TTS_DTYPE` env (`q8` | `fp32`)
  for A/B.
- `synthesize(text)` → `{audio, samplingRate}`. Errors are wrapped in a typed
  `TTSError` (`:inference` | `:loading`).
- Language support: a small map `language -> model id` (data-driven; MVP only
  `spanish -> Xenova/mms-tts-spa`). Unknown language → 422 `unsupported_language`.

### 2. WAV encoder (`src/wav.mjs`)

- Standard 44-byte-header WAV, 16-bit PCM little-endian, mono, at the model's
  sampling rate (16 kHz). Unit-testable pure function.

### 3. Route wiring (`src/server.mjs`)

- Validate: missing `text` → 422 `missing_text`; blank after trim → 422
  `empty_text`; length > `TTS_MAX_TEXT_LENGTH` → 422 `text_too_long`.
- If not ready → 503 `not_ready`; synthesis failure → 500 `synthesis_failed`.
- Success → 200, `Content-Type: audio/wav`, `Content-Length`,
  `X-TTS-Model`, `X-TTS-Duration-Ms`.
- `GET /readyz` now reflects the real readiness flag (flip the T0001 stub).

### 4. Load-on-boot & first-start download

- `load()` runs at startup **before** the server accepts synthesis (readiness
  gates it). First start downloads the model (~38 MB) into `TTS_CACHE_DIR`;
  subsequent starts load from cache. Log download progress milestones.

## Acceptance criteria

- [ ] `POST /v1/tts` returns a WAV that `ffprobe`/`file` identifies as PCM
      16 kHz mono and that a browser plays via `decodeAudioData`.
- [ ] Validation errors match `PRD.md` §7 codes (missing/blank/too-long,
      unsupported language).
- [ ] Model loads once and is reused across requests; `readyz` flips to 200 only
      after load.
- [ ] Correct `X-TTS-Duration-Ms` header (matches actual audio length).
- [ ] Synthesis failures return 500 with a typed error body, never hang.
- [ ] With `TTS_DTYPE=fp32` the same flow works (quality A/B path).

## Verification

- `node src/server.mjs`; `curl -XPOST :8080/v1/tts -d '{"text":"Hola"}' -o hola.wav`;
  play `hola.wav`; verify headers with `curl -i`.
- `curl -XPOST` with no text / blank / 2000-char text / `{"language":"klingon"}` →
  assert the documented 422 codes.
- Kill and restart → model loads from `TTS_CACHE_DIR` (fast, no re-download).
- Integration test with `node:test`: spin the server, assert 200 + WAV header on
  valid input, assert 422 codes, assert 503 while loading.
- From the umbrella root, `mix precommit` (no Phoenix regressions expected).
