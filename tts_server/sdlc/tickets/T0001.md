----
title: Scaffold the TTS server (HTTP server, config, health endpoints, Dockerfile)
----

Stand up the Node.js TTS service skeleton: a plain `node:http` server with
configuration via environment variables, liveness/readiness endpoints, and a
multi-stage Dockerfile. No synthesis yet (T0002 wires the model). This is the
foundation of the new standalone project seeded in `tts_server/`.

## Desired architecture

```text
src/server.mjs (node:http)
   |-- GET /healthz   -> 200 {"status":"ok"}          (liveness, process up)
   |-- GET /readyz    -> 200 / 503 {"status":...}     (readiness, gated on model)
   `-- POST /v1/tts   -> 503 {"error": not_ready}     (stub until T0002)

config -> env vars (HOST, PORT, TTS_MODEL, TTS_DEFAULT_LANGUAGE,
                    TTS_MAX_TEXT_LENGTH, TTS_MAX_QUEUE, TTS_SYNTH_TIMEOUT_MS,
                    TTS_CACHE_DIR)
```

## Scope

### 1. Project scaffold

- `package.json` (type: module, engines node >= 22, dependency
  `@huggingface/transformers` ^4.2.0 with the same
  `onnxruntime-web` 1.27.0 `overrides` pin used by `soundai`'s assets).
- `src/server.mjs`, `src/tts.mjs`, `src/queue.mjs`, `src/wav.mjs` module
  skeletons with exported signatures documented in the file headers (contents
  land in T0002/T0003a).
- Plain `node:http`, no framework.

### 2. Config module

- Read env vars with sane defaults (see `TECHNICAL_NOTES.md` §5 table).
- Fail fast on invalid numeric envs (e.g. non-numeric `PORT`).

### 3. Health endpoints

- `GET /healthz` → always `200 {"status":"ok"}` once the process is up.
- `GET /readyz` → `503 {"status":"starting"}` until the TTS module reports
  ready, then `200 {"status":"ready"}`. In T0001 the readiness flag is a
  constant `false` stub that T0002 flips when the model loads.

### 4. Stub `/v1/tts`

- Accepts the JSON body shape documented in `PRD.md` §7, validates JSON
  parseability (else 400), and returns `503 not_ready` (model not loaded yet).

### 5. Dockerfile

- Multi-stage on `node:22-slim` as sketched in `TECHNICAL_NOTES.md` §6; runs as
  the non-root `node` user; exposes 8080; `CMD ["node", "src/server.mjs"]`.

## Acceptance criteria

- [ ] `npm start` boots the server; `GET /healthz` returns 200.
- [ ] `GET /readyz` returns 503 (stub readiness) until T0002 flips it.
- [ ] `POST /v1/tts` with malformed JSON returns 400; valid JSON returns 503
      `not_ready`.
- [ ] Config comes from env with defaults; bad numeric env values fail fast at
      boot.
- [ ] Docker build succeeds and the image runs with the same behavior.

## Verification

- `curl localhost:8080/healthz` / `/readyz`; `curl -XPOST localhost:8080/v1/tts`
  with valid and malformed JSON.
- `docker build -t tts-server:dev . && docker run -p 8080:8080 tts-server:dev`
  and repeat the curls.
- From the umbrella root run `mix precommit` to confirm no regressions in the
  Phoenix apps (this ticket is additive — new folder only).
