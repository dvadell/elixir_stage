----
title: Layout & core component fixes (placeholder links, flash ids, input attrs, render cost)
----

Generator-leftover issues in `layouts.ex` and `core_components.ex`: broken
navigation, id collisions, crash-y component edges, and per-render waste.

## Scope

### 1. Header navigation (`components/layouts.ex:50-55`)

"Website" and "GitHub" both link to `/`, same as "Get Started" — misleading
placeholders on a single-page app. Replace with real destinations or remove
them (recommended: drop the dead links; keep Settings + theme toggle + one
CTA).

### 2. Phoenix version lookup per render (`layouts.ex:45`)

`Application.spec(:phoenix, :vsn)` runs on every layout render. Hoist to a
module attribute (compile-time constant).

### 3. Flash rendering cost (`layouts.ex:96-99`) & id collisions (`core_components.ex:59`)

- `flash_group` always renders info+error components even when empty; gate
  each with the existing render condition (`:if={Phoenix.Flash.get(@flash, @kind)}`).
- The auto flash id `"flash-#{kind}"` collides if the same kind renders twice
  and makes `hide("##{@id}")` target all duplicates. Add a unique suffix.
  Check tests/selectors referencing `#flash-info` etc. and update.

### 4. Component hardening (`core_components.ex`)

- Button variant lookup uses `Map.fetch!` with keys `"primary"`/`nil`
  (`:109`) — an atom `:primary` raises KeyError. Use `Map.get(variants,
  assigns[:variant], "btn-primary btn-soft")`.
- `attr :options, :list` has no default (`:183`) — `type="select"` without
  options raises inside `options_for_select/2`. Default to `[]`.
- Inputs without `field` **and** `name` silently drop values on submit
  (worst for hidden inputs, `:203`). Raise a descriptive error when both are
  missing so misuse fails loudly at dev time.

## Tests

- Layout test: header contains no `href="/"` duplicates for Website/GitHub;
  version string present.
- Component tests: two flashes of the same kind produce distinct DOM ids;
  empty flash map renders no alert nodes; `variant={:primary}` doesn't raise
  and yields default classes; select without options renders an empty select;
  hidden input without field/name raises ArgumentError with a clear message;
  unchecked-checkbox case added while touching inputs.
- Full controller/home tests stay green after nav changes.

- [ ] No placeholder/misleading navigation remains.
- [ ] Flash ids are collision-free; empty flashes cost nothing.
- [ ] Misused components fail loudly instead of dropping data or raising
      cryptic errors.
