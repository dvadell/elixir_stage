----
title: Add a text-to-speech engine
----

Implement browser-side speech-to-text (STT) in the Phoenix application using **Transformers.js + Whisper**, preferring **WebGPU** for inference and falling back to **WASM/CPU** when WebGPU is unavailable.

The browser should capture microphone audio, transcribe it locally and log it to the console as it is working now.

## Desired architecture

```text
Browser
  |
  | microphone audio
  v
MediaRecorder / AudioContext
  |
  v
Transformers.js
  |
  +--> WebGPU (preferred)
  |
  +--> WASM/CPU (fallback)
  |
  v
Whisper
  |
  v
transcribed text
  |
  v
console.log
```

The raw microphone audio should **not** need to be uploaded to Phoenix for transcription.

## Scope

### 1. Add Transformers.js

- Add `@huggingface/transformers` to the frontend JavaScript dependencies.
- Integrate it with the existing Phoenix asset/build pipeline.
- Verify that the application can load an appropriate Whisper ONNX model in the browser.
- Configure model loading so that browser caching can be used after the initial download.

### 2. Implement Whisper transcription

- Select an appropriate multilingual Whisper model.
- Start with a small model suitable for browser inference (for example, Whisper tiny/base or an appropriate distilled/quantized variant).
- The model must support Spanish.
- Keep the model choice/configuration easy to change after benchmarking.

### 3. WebGPU with WASM fallback

Prefer WebGPU when available:

```text
WebGPU available
    -> Transformers.js / Whisper on WebGPU

WebGPU unavailable
    -> Transformers.js / Whisper on WASM/CPU
```

The application should detect WebGPU availability and select the appropriate Transformers.js device.

Do not make WebGPU a hard requirement.

### 4. Microphone capture

Implement browser microphone capture using the Web Audio APIs.

Requirements:

- Request microphone permission only when the user initiates voice interaction.
- Capture audio in a format that can be consumed by Whisper.
- Handle permission denial gracefully.
- Handle browsers/devices without microphone support gracefully.
- Avoid sending the raw audio to the Phoenix backend.

### 5. Voice UI integration

Integrate the STT functionality into the existing voice-assistant UI.

The UI should expose at minimum:

- Idle state
- Listening/recording state
- Transcribing state
- Error state
- Transcribed text/result

The UI should make it clear when the microphone is actively recording.

The backend should not need to know whether transcription was performed with WebGPU or WASM.

### 7. Error handling

Handle at least:

- Microphone permission denied
- No microphone available
- WebGPU unavailable
- WASM initialization failure
- Whisper model download failure
- Whisper inference failure
- Browser incompatibility
- Network failure while initially downloading the model

Errors should be surfaced to the user without crashing the LiveView/application.

## Performance requirements

- Do not block the browser's main UI thread during model loading or inference.
- Prefer a Web Worker for Whisper initialization and inference if practical.
- Avoid loading the Whisper model repeatedly for every utterance.
- Keep the model loaded and reusable for subsequent transcriptions.
- Benchmark first transcription separately from subsequent transcriptions, since the initial model download/loading will be substantially more expensive.

## Model caching

The Whisper model should be cached by the browser so that subsequent sessions do not require downloading the complete model again when the browser cache is available.


## Acceptance criteria

- [ ] The Phoenix application can request microphone access from the browser.
- [ ] A recorded utterance can be transcribed locally using Whisper.
- [ ] Transformers.js uses WebGPU when WebGPU is available.
- [ ] Transformers.js falls back to WASM/CPU when WebGPU is unavailable.
- [ ] Spanish speech is transcribed correctly enough for the voice-assistant use case.
- [ ] Raw microphone audio is not sent to Phoenix for STT.
- [ ] The Whisper model is initialized once and reused for multiple utterances.
- [ ] Model assets are cached by the browser.
- [ ] The UI clearly communicates listening, transcription, and error states.
- [ ] Microphone permission denial is handled gracefully.
- [ ] WebGPU/WASM initialization errors are handled gracefully.
- [ ] Whisper inference does not freeze the main browser UI.
- [ ] The resulting text is logged in the console
- [ ] The implementation works on at least one WebGPU-capable browser and one WASM-only/fallback environment.
- [ ] Basic performance measurements are documented.

## Benchmark methodology

The goal is a measurable, repeatable comparison for the three target environments.

### Environments to benchmark

| Environment | Expected device | GPU |
|-------------|-----------------|-----|
| Chrome (WebGPU) | `webgpu` | discrete GPU |
| Chrome + `--enable-features=SharedArrayBuffer` via the app's COOP/COEP headers (WASM) | `wasm` | disabled |
| Firefox (WASM, threads not required) | `wasm` | disabled/software |

For forcing a WASM run in Chrome, disable WebGPU (`chrome://flags` or
`--disable-features=WebGPU`). Forcing device selection: per-development you may use
`?model=onnx-community/whisper-small&language=spanish` to A/B the model/language
config on any of these environments; model/dtype defaults live in
`apps/soundai/assets/js/whisper_config.js`. At minimum, test that both `deviceTypes`
(`webgpu` and `wasm`) run.

### Metrics to collect

First interaction (unprimed):

1. **Model load time** — first `ensureInit` full duration (download + compile). Read from the
   DevTools Network/Performance or from the milestone logs (init started → ready).
2. **First transcription latency** — `pointerup` → first `final` transcript message, including
   model init when unprimed.
3. **First token timing histogram** — Whisper decode `tokens_decoded` spread, per transcription,
   to see perceived responsiveness.

Subsequent interactions (primed):

4. **Stable transcription latency** — `pointerup` → `final` on a primed model (nominal).
5. **Capture overhead** — `MediaRecorder` timestamps and a 200ms minimum-utterance threshold
   mean the captured window ≈ the speaking duration plus ~200ms; no VAD or FFT loop is used.

### Procedure

- Use the same 5–10s Spanish utterance for every run, repeated as a 3-run median.
- Record ambient `preparing?` progress to capture download speeds when transferring a cold cache.
- Log `device` and `progress` milestones from the hook to console; collect from the DevTools
  console, then paste into the ticket's final status.

### Notes for the final report

- Report the Whisper variant + quant used (`onnx-community/whisper-base` with hybrid
  `fp32` encoder + `q8`/`fp16` decoder), cached vs cold.
- Cross-origin isolation headers (COOP/COEP) are served by the endpoint; this unlocks
  onnxruntime-web's WASM thread pool (defaults to `numThreads` from
  `hardwareConcurrency`). Report the speedup of threaded vs single-threaded WASM.
- Report whether `allow_localhost_pool: /cache/` was reachable, and the shared-cache hit impact.
- Keep `data_files` pinned so that the model's exact files are reproducible.
- Capture can be re-triggered while the model is downloading; the very first transcription
  will implicitly wait for the download to finish, so its time is dominated by the download.
