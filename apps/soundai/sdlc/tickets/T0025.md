----
title: LLM seam & API-edge error normalization
----

Several failure paths at the LLM boundary escape the documented contract or
crash instead of returning clean errors: exceptions from the upstream
`branched_llm` call propagate to a 500, unknown error atoms raise
`FunctionClauseError`, unknown JSON templates render `nil` details, and
client-supplied context params are relayed raw.

## Scope

### 1. Normalize upstream failures (`conversation/llm.ex:14-16`)

`LLM.call/3` forwards straight to `BranchedLLM.Chat.send_message/3`; any
exception/unexpected return breaks the "never raises" seam contract relied on
by `Soundai.Conversation.do_submit/3`. Wrap the delegation in
`try/rescue` + `catch` (incl. `:exit`) normalizing everything to
`{:error, reason}`. Also fix the moduledoc (`llm.ex:6-7`): the `:adapter`
injection seam lives in `Soundai.Conversation.adapter/0`, not here.

### 2. Catch-all error message (`transcription_controller.ex:94-96`)

`reason_message/1` only covers `:empty/:too_long/:invalid`; any new atom from
the conversation layer crashes this public endpoint with a 500. Add a
catch-all clause returning the generic message (and log the unexpected
reason).

### 3. Safe ErrorJSON fallback (`soundai_web/controllers/error_json.ex:18-20`)

Unknown/non-status templates render `%{errors: %{detail: nil}}`. Add a
catch-all `render/2` returning `"Internal Server Error"` so detail is never
nil.

### 4. Validate input at the edge (`conversation_audio_controller.ex:33,75-83`)

- The audio endpoint passes raw `text` to `submit_transcript` without the
  presence/length checks the transcription endpoint applies — enforce the
  same caps here (empty → 422, over-long → 413/422 per existing convention)
  before spending LLM/TTS resources.
- Explicitly normalize/whitelist `date`, `time`, `timezone`, `latitude`,
  `longitude` (format checks / float parse + range) and drop invalid values,
  rather than relying solely on downstream re-validation. Defense-in-depth
  against prompt-content injection via these fields.

Note: rate limiting/auth for these endpoints is out of scope here — see the
T0019 spike.

## Tests

- Fake adapter raising / exiting / returning `{:ok, resp}` (2-tuple) /
  returning nil → endpoints still return mapped JSON errors (502 family),
  never 500-with-crash.
- Unknown reason atom injected via fake adapter → generic message, no
  `FunctionClauseError`.
- Render an unknown template through `ErrorJSON` → detail is
  `"Internal Server Error"`.
- Audio endpoint: missing text → 422; oversized text → capped error; garbage
  lat/long/date dropped while valid values reach the conversation meta
  (assert via fake capture pid opts).

## Acceptance criteria

- [ ] No input or adapter misbehavior can produce an unhandled crash on the
      public endpoints.
- [ ] The LLM seam contract (`{:ok, _, _} | {:error, _}`) holds for all
      upstream behaviors.
- [ ] JSON error bodies never contain `nil` details.
