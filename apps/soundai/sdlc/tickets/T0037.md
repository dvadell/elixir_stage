----
title: TTS tests decoupled from runtime/deployment state
----

Several TTS tests pass or fail depending on whether a real ONNX model file
happens to exist and whether the supervised OrtexServer is running —
environment-coupled flakiness.

## Scope

### 1. `test/soundai/tts_test.exs:48-52` (high)

The `{:error, :not_ready}` test relies on *no* `Soundai.TTS.OrtexServer`
process being registered; if a model file exists at the configured path, the
real server starts, loads, and can return success (or block on load). Rewrite
using the existing adapter seam: inject a fake returning
`{:error, :not_ready}` for the "unavailable" contract, and use
`start_supervised!` with an explicit nonexistent model path where the real
server's not-ready behavior itself is under test.

### 2. `test/soundai_web/controllers/tts_controller_test.exs:71-76`

The 503 path injects the real adapter and assumes runtime `:not_ready`. Use a
fake adapter returning `{:error, :not_ready}` so the controller mapping is
tested deterministically.

### 3. Fake conversation adapter error-path capture
(`test/support/conversation_fake_adapter.ex:23-28`)

When `fake_error` is set, `call/3` returns before sending the capture
messages, so tests cannot distinguish "adapter never called" from "adapter
called and errored" and may pass trivially. Emit `:fake_llm_called/text/opts`
before returning the error tuple (mirroring the success path).

### 4. TTS fake adapter fidelity (`test/support/tts_fake_adapter.ex`)

`duration_ms: 1` / `sample_rate: 16000` are magic numbers unrelated to the
canned WAV, and `wav()` re-encodes on every call. Derive both from one
compile-time `Wav.encode_to_map([0.0])` module attribute so the fake always
matches the real envelope shape (and gets faster).

## Tests

- Suite passes with `SOUNDAI_TTS_MODEL_PATH` pointing at a nonexistent file
  AND at a real model file (both env matrices green).
- New assertion: with `fake_error` set, capture pid receives the call
  messages (proves the fix).
- Controller 503 test no longer references the real OrtexServer.

## Acceptance criteria

- [ ] No soundai TTS test depends on model-file presence or global process
      registry state.
- [ ] Error-path adapter invocation is observable in tests.
- [ ] Test fakes derive their metadata from the real encoder.
