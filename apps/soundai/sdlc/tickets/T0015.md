----
title: Client — reply modes (server = audio, native/local = text) + conversation cookie
----

Wire the browser to the two server paths from T0013/T0014, tying the reply mode
to the existing TTS engine picker (decision):

- **TTS engine = `server` ("Servidor (Elixir + ONNX)")** ⇒ audio mode: POST the
  transcript to `/api/conversations/audio`, receive WAV, play it. The server
  runs the LLM and synthesizes the answer in one round trip.
- **TTS engine = `native` / local VITS** ⇒ text mode: POST to
  `/api/transcriptions`, speak the LLM text with the selected engine (this is
  mostly the current behavior, just with a real LLM answer).

The `soundai_conversation` cookie flows automatically with same-origin `fetch`
— no client cookie code needed. The send/speak watchdog and quiet-note
timeouts from T0011 must keep working for both modes.

## Scope

### 1. `voice_assistant.js` — mode dispatch in `sendTranscript`

- Determine mode from the active engine id (`this.ttsEngine.engineId` — add a
  small accessor or pass the id at construction):
  - **Audio mode** (`server`): `fetch("/api/conversations/audio", {method:
    "POST", headers: {"Content-Type": "application/json"}, body:
    JSON.stringify({text, language})})`. On success: `arrayBuffer()` → play via
    the existing server playback path (share `ServerTTSEngine`'s audio playback
    or extract a common helper). State machine:
    `sending → speaking → result` (reuse T0011 watchdog).
  - **Text mode**: unchanged `/api/transcriptions` call; speak
    `responseData.response` via native/local engine.
- On **503 from the audio endpoint** (server TTS model absent): fall back to
  **text mode** for this utterance — POST to `/api/transcriptions`, speak the
  reply with the native engine — with a quiet note
  (e.g. "El servidor no pudo generar audio — respuesta en texto."). Never the
  error state.
- On LLM failure (502/504/network): keep the transcript visible with the
  existing quiet "couldn't reach the server" note; never the error state.
- `pointerdown` still calls `ttsEngine.cancel()` so a new recording interrupts
  audio playback in both modes.

### 2. `tts_engine.js` — `ServerTTSEngine` no longer used for "server" replies

- The `server` engine's job changes: in audio mode the whole conversation reply
  is server-side, so `voice_assistant.js` does not call the engine's
  `speak(text, ...)` for the LLM text anymore. Keep the class as the playback
  path for the WAV returned by `/api/conversations/audio` (or move that logic
  into `voice_assistant.js` and delete the old `/api/tts` `speak` usage).
- Keep the engine interface intact (init/isReady/speak/cancel) so the settings
  picker and existing fallbacks still work. Register the id so
  `createTTSEngine("server")` keeps resolving.
- Update the `ServerTTSEngine._checkEndpoint` probe: it currently POSTs to
  `/api/tts` with blank text; point it at `/api/conversations/audio` (blank text
  is 4xx — still proves reachability) so readiness matches the audio path.

### 3. `/settings` copy (`SettingsHTML.tts_models/0`)

- Update the "Servidor" option label/description to convey the new meaning,
  e.g. label "Servidor (respuesta de voz)" / description "El servidor responde
  por voz (LLM + síntesis en una sola llamada)." Keep the id `server` so saved
  cookies keep working. Review the `soundai_tts` cookie precedence
  (`?tts=` > cookie > `"native"`).

### 4. Offline-first discipline (unchanged contract)

- STT stays fully local/offline. Audio mode requires the server; when
  `navigator.onLine === false` skip the POST and keep the transcript with the
  existing offline note. Text mode remains best-effort.

## Acceptance criteria

- [ ] `server` engine selection ⇒ one POST to `/api/conversations/audio`; the
      returned WAV plays and the state machine reaches `result`.
- [ ] `native`/local engine selection ⇒ `/api/transcriptions`; the LLM text is
      spoken by that engine.
- [ ] Follow-up turns carry context (the cookie round-trip) with no client-side
      conversation code.
- [ ] Audio endpoint 503 → automatic one-time fallback to text mode with a
      quiet note; LLM failure → quiet note, transcript stays; never error state.
- [ ] T0011 send/speak watchdogs still bound both modes (no unbounded waits).
- [ ] `/settings` description reflects the new "server reply" meaning.
- [ ] Manual browser verification (per convention — no E2E harness).
