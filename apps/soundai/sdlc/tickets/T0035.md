title: Frontend dependency lockfile repair & gettext POT header
----

Packaging hygiene: the npm lockfile is out of sync with the declared
transformers dependency (two onnxruntime versions in one tree), and the POT
template lacks its mandatory charset header.

## Scope

### 1. onnxruntime version mismatch (high — `assets/package-lock.json:809-818`)

`@huggingface/transformers` declares `onnxruntime-web:
1.26.0-dev.20260416-b7804b056c` (exact prerelease) but the lockfile resolved
**1.27.0**, which does not satisfy the range. Additionally the tree carries
two `onnxruntime-common` versions (1.27.0 under web, 1.24.3 under node) —
unpredictable behavior when both backends are exercised.

Fix: run `npm install` in `apps/soundai/assets` to regenerate a consistent
lockfile; prefer moving the declaration to a stable release (e.g.
`^1.27.0`) if the transformers package permits, or pinning the exact resolved
version everywhere. Verify `npm ci` reproduces cleanly with a single
onnxruntime-common.

### 2. Deprecated transitive dep (low — `package-lock.json:595-599`)

`boolean` (via `global-agent`/`roarr` under `onnxruntime-node`) is
unmaintained. No action beyond recording it here; re-check when bumping
onnxruntime-node.

### 3. POT header (`priv/gettext/default.pot:11-12`)

The template's `msgid ""` block is missing the mandatory
`Content-Type: text/plain; charset=UTF-8` header — gettext tooling can't
reliably interpret encoding. Fix by running `mix gettext.extract --merge`
(after ensuring the Gettext backend config emits headers) or adding the
header line manually; commit the regenerated file.

## Tests

- `cd apps/soundai/assets && npm ci` succeeds reproducibly;

  tree.
- Browser STT still works after the dependency change — manual matrix:
  WebGPU path (Chrome), WASM fallback (Firefox), model cached offline reload.
- `mix gettext.extract` produces no diff churn after the header fix.
