----
title: Conversation context store + LLM relay (text mode)
----

Replace the echo in `Soundai.Conversation` with a real LLM call through
`branched_llm`, maintaining per-conversation context server-side. This is the
text-mode path (`POST /api/transcriptions`); T0014 adds the audio path reusing
the same seam.

## Desired architecture

```text
Browser (text mode)
  | POST /api/transcriptions  {text, language}   (+ soundai_conversation cookie)
  v
TranscriptionController
  | fetch_cookies(conn) → conversation_id
  v
Soundai.Conversation.submit_transcript(text, conversation_id)
  |  load/create ReqLLM.Context in Soundai.Conversation.Store
  |  BranchedLLM.Chat.send_message(text, context, timeout: ...)
  |  store updated context (user + assistant turns)
  v
{:ok, response_text, conversation_id}  |  {:error, reason}
  v
201 {"ok": true, "response": <LLM text>, "conversation_id": "...", "language": "..."}
  + Set-Cookie: soundai_conversation=<id>; HttpOnly? (see §4)
```

## Scope

### 1. `Soundai.Conversation.Store` (in-memory context store)

- New GenServer (or ETS + cleanup) keyed by `conversation_id` storing the
  `ReqLLM.Context` returned by `Chat.send_message/3`.
- Idle TTL (default e.g. 30 min; configurable under `config :soundai,
  Soundai.Conversation`): conversations are dropped when idle, so memory is
  bounded. First request with `conversation_id == nil` creates a fresh context
  and a fresh id.
- `start_supervised!` / add to `Soundai.Application`'s supervision tree.
- Provide `get/1`, `put/2`, `delete/1` (or `get_or_new/1`). Mirror the existing
  `OrtexServer` serialization discipline: no locks needed here, but keep all
  state access in the owning process.

### 2. `Soundai.Conversation.submit_transcript/2`

Signature change: `submit_transcript(text, conversation_id \\ nil)` returning
`{:ok, response_text, conversation_id}` | `{:error, reason}`.

- Keep the existing validation (`@max_text_length` 4000, trim, empty/invalid).
- Build/load the context with a **Spanish voice-assistant system prompt**
  (configurable under `config :soundai, Soundai.Conversation`), e.g.:

  > "Eres un asistente de voz amable y directo. Respondes en español, de forma
  > breve y natural, como en una conversación hablada, sin listas ni encabezados."

- Call the LLM through an **injectable adapter** (mirror the `Soundai.TTS`
  `:adapter` pattern — see `lib/soundai/tts.ex`):
  - default `Soundai.Conversation.LLM` → `BranchedLLM.Chat.send_message/3`
    with `timeout:` from config (default 30 s), `max_tokens:` cap (e.g. 300).
  - tests inject `Soundai.Conversation.LLM.FakeAdapter`.
- On success persist the returned context and return the response text. Cap the
  returned text length (e.g. 500 chars with a trailing "…") so TTS latency stays
  sane; configurable.
- On LLM error map to a stable reason (e.g. `:llm_unavailable`, `:llm_timeout`)
  that the controller renders as a JSON error — never raise.

### 3. `TranscriptionController#create`

- Add `plug :fetch_cookies` to the `:api` pipeline in `router.ex` (or call
  `fetch_cookies(conn)` here) so `conn.cookies["soundai_conversation"]` is
  readable.
- Accept an optional `conversation_id` in the body (precedence: body param >
  cookie) so tests and non-cookie clients can drive context.
- On success: `put_resp_cookie("soundai_conversation", id, max_age: ..., path: "/", same_site: "Lax")`,
  return `201 {"ok": true, "response": <text>, "conversation_id": <id>, "language": ...}`.
- On `{:error, :llm_unavailable}` / `{:error, :llm_timeout}` return a 502/504
  JSON error the client treats as a **quiet note**, not the error state.

### 4. Security / privacy

- The cookie is a random opaque id (server-generated), not a session. Do not
  put user text in it. Plain non-HttpOnly cookie is acceptable for now (no
  auth exists); note PRD §14 (rate limiting/auth before public deployment).
- User text remains untrusted: keep the existing validation.

## Acceptance criteria

- [ ] `submit_transcript/2` returns the **LLM's** text, not the echo, and the
      controller returns it in `response` with a `conversation_id`.
- [ ] A second turn with the same conversation_id sees prior context (fake
      adapter asserts it received the previous assistant turn).
- [ ] `nil`/unknown conversation_id starts a new conversation.
- [ ] Idle conversations expire (TTL) — covered by a unit test (no sleeps;
      drive the GenServer directly).
- [ ] LLM errors map to 502/504 JSON without crashing.
- [ ] `TranscriptionControllerTest` rewritten to use the fake LLM adapter;
      existing validation tests (missing/blank/oversized → 422) still pass.
- [ ] The audio endpoint (T0014) will reuse `Soundai.Conversation` unchanged.
