----
title: Theme system consistency (dark variant vs daisyUI prefersdark) & CSS hygiene
----

The dark-mode machinery has two selection mechanisms that can disagree:
Tailwind's custom `dark:` variant keys off `[data-theme=dark]`
(`assets/css/app.css:96`) while the daisyUI dark theme registers
`prefersdark: true` (auto-applies from OS preference without setting the
attribute). If any render path relies on daisyUI's auto-selection, daisyUI
components go dark while `dark:` utilities stay light — inconsistent theming.
Today the inline script in root.html.heex sets `data-theme`, which likely
masks this; the ticket is to prove it and remove the ambiguity.

## Scope

1. **Audit the flow**: trace how `data-theme` / `data-theme-source` get set
   (root.html.heex inline script + app.js theme toggle) for all three modes
   (system/light/dark) and both OS preferences. Confirm whether daisyUI's
   `prefersdark` can ever activate independently of the attribute.
2. **Align mechanisms**: either set `prefersdark: false` on the daisyUI dark
   theme (attribute becomes the single source of truth) or make the inline
   script always resolve "system" to a concrete `data-theme=dark|light`
   before first paint. One mechanism, documented in TECH_DESCRIPTION.
3. **Slider coupling**: the toggle slider positions via attribute selectors
   like `[[data-theme-source=system]_&]:!left-0` (`layouts.ex:113`) that only
   work because the inline script sets exactly those values — verify the
   selector values match what the script writes (rename together if touched).
4. **Accessibility**: add `aria-label`/`title` ("Tema del sistema", "Tema
   claro", "Tema oscuro") to the three icon-only buttons.
5. **Trivial**: terminate the `[hidden]` declaration with `;`
   (`app.css:100`).

## Tests

- Manual visual matrix: {system→light, system→dark, light, dark} × fresh load
  vs toggle — check both daisyUI-styled elements (btn/card) and `dark:`
  utilities switch together; no flash of wrong theme on reload.
- Grep/assertion: only one mechanism selects darkness (post-change).
- Slider lands under the active icon in all three states.

## Acceptance criteria

- [ ] Exactly one source of truth decides dark styling.
- [ ] Toggle buttons are labelled for screen readers.
- [ ] Visual matrix passes on Chrome + Firefox, light and dark OS prefs.
