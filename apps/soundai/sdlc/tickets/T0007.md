----
title: Local Transformers.js TTS engine (TTS worker + config + playback)
----

Add the **local text-to-speech engine** on top of the pluggable TTS
architecture introduced in T0006: the assistant synthesizes Spanish speech in
the browser using **Transformers.js** models (VITS) in a dedicated Web Worker,
preferring WebGPU and falling back to WASM/CPU — exactly mirroring how Whisper
runs for STT. The native API remains the automatic fallback for any
local-engine failure and stays selectable from `/settings`.

This is the ticket that makes the local options in the `/settings` picker
actually work.

The product loop stays `... sending -> speaking -> result`; only the audio
source changes.

## Desired architecture

```text
Browser
  |
  | server response text
  v
voice_assistant.js (speakResponse)
  |
  v
createTTSEngine(engineId)      <- tts_engine.js registry (T0006)
  |
  +--> transformers (this ticket)
  |      |
  |      v
  |   tts_worker.js (Web Worker, VITS TTS, WebGPU -> WASM)
  |      |
  |      v
  |   Float32Array audio @16 kHz
  |      |
  |      v
  |   Web Audio API (AudioContext) -> speaker
  |
  +--> native (T0006)  <-- automatic fallback on any local failure
```

Audio stays entirely local: no server-side synthesis, no audio leaves the
device (PRD §11, §20).

## Scope

### 1. TTS config — single source of truth

- New `apps/soundai/assets/js/tts_config.js` exporting `TTS_CONFIG`:
  - `engine`: default engine id (the resolved default used by
    `voice_assistant.js` when no `?tts=` param or `soundai_tts` cookie is set).
    Default to `Xenova/mms-tts-spa` once the local engine is proven working.
  - `models`: ordered list of **local** transformers.js model options, each with
    `id` and per-device `dtype` (mirroring `WHISPER_CONFIG.dtype` shape). Start
    with:
    - `Xenova/mms-tts-spa` — default. VITS, 16 kHz, ~38 MB quantized
      (`model_quantized.onnx`), fp32 `model.onnx` ~114 MB. Good Spanish quality
      for a ~36M-param model; light enough for the target users' devices.
    - `onnx-community/Supertonic-TTS-2-ONNX` is **not** enabled here — it is
      benchmarked and added in T0008.
  - `dtype` guidance: prefer `q8` on WASM and `fp16` on WebGPU, per device, the
    same way `WHISPER_CONFIG.dtype` works. TTS is far less quantization-sensitive
    than Whisper's encoder, so a fully quantized model is acceptable here.
  - Note for implementers: `Xenova/speecht5_tts` is **not** suitable (English
    only + requires speaker embeddings) — do not add it.
- Keep `TTS_CONFIG.models` in sync with the server-rendered option list in
  `SettingsHTML` (`@tts_models`, added in T0006; §12 of the technical
  description).

### 2. TTS Web Worker

- New `apps/soundai/assets/js/tts_worker.js` mirroring `whisper_worker.js`:
  - Separate esbuild entry point with the **stable URL**
    `/assets/js/tts_worker.js` (main thread constructs
    `new Worker("/assets/js/tts_worker.js")`; the service worker precaches that
    exact path).
  - Same env setup: `env.useBrowserCache = true`, `env.useWasmCache = true`,
    `env.allowLocalModels = false`, `LogLevel.WARNING`.
  - Loads the Transformers.js **`text-to-speech`** pipeline
    (`pipeline("text-to-speech", modelId, {device, dtype, progress_callback})`).
  - WebGPU → WASM fallback identical to `whisper_worker.js` (§5.2 of the
    technical description): retry with `wasm` on runtime failure and post a
    `fallback` message.
  - Message protocol (mirror the whisper worker's shape):
    ```text
    main -> worker  {type: "init", options: {device, model, dtype}}
                    {type: "synthesize", id, text}
    worker -> main  {type: "progress", status, progress, ...}
                    {type: "ready", device}
                    {type: "fallback", from, to, error}
                    {type: "audio", id, audio: Float32Array, sampling_rate, device, inferenceMs}   (transferable)
                    {type: "error", stage, error}
    ```
  - The synthesizer is initialized once and reused across turns (no repeated
    downloads). Changing the selected model reloads the pipeline (config-change
    detection like `whisper_worker.js`).

### 3. Transformers engine + playback

- New `transformers` engine class in `tts_engine.js` (T0006's registry gains it):
  - `init()` — resolves the model from `TTS_CONFIG`, creates the worker, posts
    `init`, awaits `ready` (reusing the device detection / WebGPU probe pattern
    from `voice_assistant.js::detectDevice`).
  - `speak(text, language, {onend, onerror})` — posts `synthesize` with the text;
    on the `audio` result, plays the returned `Float32Array` via a dedicated Web
    Audio `AudioContext` + `AudioBufferSourceNode` at `sampling_rate`
    (16 kHz for mms-tts-spa).
  - `cancel()` — stops the AudioBufferSourceNode and clears any pending
    synthesis (and the worker ignores/aborts stale `synthesize` results by
    generation counter).
  - `isReady()` — true after the first `ready`.
- Playback details:
  - Use a **dedicated** `AudioContext`; do **not** reuse the mic
    `AudioContext`.
  - Resume the context on user gesture / before playback (autoplay policy).
  - Stop the source on `cancel()` so the user can interrupt mid-speech.
  - Log `device`, `sampling_rate`, and `inferenceMs` (`[soundai]` prefix) for
    the manual verification and benchmarks.

### 4. Preload the local TTS model

- In `voice_assistant.js::preload()`, when the resolved engine is the
  transformers engine, initialize it **in parallel** with the Whisper preload so
  the user never waits on it while talking.
- Mirror the Whisper ready handling: worker posts `ready` → engine is ready;
  progress posts surface on the existing loading screen. Surface the TTS model
  download as a **second progress source** combined with the Whisper progress
  for the loading %, so a TTS download cannot stall the record button (STT stays
  the gate: the button becomes interactive once Whisper is ready).
- The native engine (T0006) needs no model preload.

### 5. Automatic fallback to native

- If the transformers engine fails to init or synthesize (model download
  failure, WebGPU/WASM init failure, inference failure, unsupported browser),
  `speakResponse` falls back to the **native engine** and keeps the current
  quiet-note behavior — **never** the error state (PRD §13 TTS section).
- The fallback is best-effort: if the local engine succeeds on the next
  utterance, use it again; a failed engine stays broken for the session without
  retrying in a tight loop.

### 6. Build & service worker

- `config/config.exs` (`:esbuild` `:soundai`): add `js/tts_worker.js` to the
  entry points so it is bundled to `priv/static/assets/js/tts_worker.js`.
- `priv/static/service_worker.js`: add `/assets/js/tts_worker.js` to
  `APP_SHELL` and **bump `CACHE_NAME`** (e.g. `soundai-shell-v2`) since the app
  shell changes.
- Keep the stable `/assets/js/tts_worker.js` URL (same rule as the whisper
  worker, §12 of the technical description).

### 7. Security & privacy

- No new server endpoints; no audio or text beyond the existing
  `POST /api/transcriptions` call. The `response` text is synthesized locally
  and never uploaded.
- Model weights are downloaded from the HF CDN and cached in the browser Cache
  Storage (same as Whisper); no credentials involved.
- TTS text is untrusted server/LLM output — rendered to audio only, never
  evaluated as code.

  - Worker/protocol/fallback sections: mirror the whisper worker docs for TTS.

## Acceptance criteria

- [ ] A local transformers.js TTS model is preloaded in the browser (WebGPU
      preferred, WASM fallback) and cached by the browser for subsequent
      sessions.
- [ ] The selected local model synthesizes Spanish speech in the browser and
      plays it through the speakers; inference runs off the main thread in
      `tts_worker.js`.
- [ ] TTS inference never freezes the main browser UI.
- [ ] The `speaking` state and `onend` → `result` transition behave as before.
- [ ] Starting a new recording cancels in-flight local synthesis
      (`ttsEngine.cancel`).
- [ ] If the local engine fails to init/synthesize, the assistant automatically
      falls back to the native API with a quiet note (no error state).
- [ ] Selecting `native` from `/settings` still uses `speechSynthesis` with a
      language-matched Spanish voice.
- [ ] The local model is initialized once and reused for multiple utterances.
- [ ] `tts_worker.js` is served at its stable URL and precached by the service
      worker; `CACHE_NAME` is bumped.
- [ ] Raw audio and TTS output never leave the browser; no new server
      endpoints.
- [ ] `TECHNICAL_DESCRIPTION.md` reflects the local TTS engine.

## Verification

- Manual browser checks (no Elixir surface to unit test; consistent with the
  existing convention):
  - Default engine: open `/`, wait for the loading screen to complete, say a
    Spanish utterance, confirm the assistant speaks the response with the local
    model. Observe `[soundai]` logs: TTS worker `ready`, `audio` result with
    `device` + `inferenceMs`.
  - WebGPU vs WASM: with WebGPU enabled the logs show `webgpu`; disable WebGPU
    (`chrome://flags` or `--disable-features=WebGPU`) and confirm the `fallback`
    to `wasm` and continued synthesis.
  - Fallback: force an engine failure (e.g. temporarily point `tts_config.js`
    at a bogus model id) and confirm a quiet note + native voice, never an error
    state.
  - Interrupt: tap the button while the local model is speaking; confirm
    playback stops and a new recording starts.
  - Offline: after the first download, reload offline and confirm both STT and
    local TTS still work.
  - `/settings`: switching between `native` and the local model is honored on
    the next load.
- Benchmark (before promoting the local engine to the default):
  - `Xenova/mms-tts-spa`: first model download/load time, primed synthesis
    latency (text → audible), synthesized-ms / wall-clock ratio, memory
    footprint (DevTools).
  - Capture the numbers into the ticket's final status / a benchmark note in
    `TECHNICAL_DESCRIPTION.md`.
- `cd apps/soundai && mix test` — the local engine has no Elixir surface, but
  run the suite to confirm nothing regressed.
- Run `mix precommit` (from the umbrella root) before considering the ticket
  done.
