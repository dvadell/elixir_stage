----
title: HTTPClient defaults & weather tool hardening
----

`Soundai.HttpClient` has no default timeout, loses error context in
telemetry, and the weather tool duplicates place-resolution logic while
trusting geocoder output it never validates.

## Scope

### 1. HttpClient defaults (`http_client.ex`)

- **Default timeout (high)**: requests can hang indefinitely when callers
  pass no timeout (the only caller, `weather.ex`, doesn't). Merge a default
  `receive_timeout` (~5 s) unless explicitly overridden; keep caller opts
  precedence.
- **Telemetry stop metadata (medium)**: the error path emits `%{}` — include
  `%{error: reason, url: url}` so failures are diagnosable. Note
  `:telemetry.span/4` drops the stop event if the function raises; wrap the
  request so exceptions still emit a stop (status `:exception`) before being
  re-raised.
- **Early validation (low)**: `Keyword.fetch!(opts, :url)` instead of a nil
  url silently landing in span metadata.
- **Optional (low)**: generic `request(method, url, opts)` wrapper that
  `get/2` delegates to, keeping the telemetry span centralized for future
  verbs.

### 2. Weather tool (`conversation/tools/weather.ex`)

- **Dedupe resolution logic (medium)**: location-vs-coordinates precedence is
  implemented twice (`current/1` ~112-141 and the daily path). Extract one
  shared `resolve_place/1` used by both so rules/error strings can't drift.
- **Validate geocoder output (medium)**: geocoded lat/lon are forwarded
  unvalidated (~250-256) unlike user-supplied coords which go through
  `valid_coordinates?/1`. Normalize through the same check before returning
  `{:ok, place}`.
- **Nil-safe summarize (low)**: `summarize/2` interpolates current-weather
  keys without guards (~326-331); schema drift would render "humedad nil
  porciento". Use a guarded extraction helper (consistent with
  `summarize_day/3`) falling back to "N/A"-style wording.
- **Optional (low)**: short-TTL cache (ETS) for geocode results keyed by
  normalized location name — same city repeats within a conversation today.

## Tests

- Hung transport (Req.Test plug that never responds) → request fails within
  the default budget with a timeout reason; explicit override still wins.
- Telemetry: attach a test handler; assert stop event carries error metadata
  on failure and status/timing on success; raising plug still emits stop.
- Weather: geocoder stub returning out-of-range coords → clean error tuple,
  no malformed forecast call issued.
- Missing keys in forecast payload → summary text degrades gracefully.
- Shared resolver unit test: blank-location + valid coords, blank + invalid
  coords, non-blank location precedence — asserted once via the extracted
  helper (plus one integration assertion per endpoint path).
- Optional cache: second identical geocode hits the stub once.

## Acceptance criteria

- [ ] No external HTTP call can hang past the default budget.
- [ ] Failure telemetry explains *why* a request failed.
- [ ] Place-resolution precedence exists in exactly one place.
- [ ] Geocoder output is validated like user input.
