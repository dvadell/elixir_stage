----
title: STT-robust system prompt (best-effort interpretation + easy-to-say answers)
----

The browser-side Whisper STT is not perfect: it occasionally splits or joins
words, mis-transcribes homophones, or drops punctuation. Today the default
system prompt in `Soundai.Conversation` asks only for short, natural answers.
Make the prompt instruct the LLM to (1) make its best effort to interpret the
garbled transcript — including words split by the STT — and answer the likely
intended message rather than asking for clarification, and (2) reply with short,
simple, easy-to-pronounce sentences using common words, so the follow-up TTS
(and any re-transcription) stays accurate.

## Scope

- `lib/soundai/conversation.ex`: rewrite `@default_system_prompt` to a Spanish
  prompt that:
  - explains the input comes from speech recognition that may split/join/mangle
    words, and asks the model to infer the intended message;
  - forbids asking for clarification or correcting the user;
  - requires short, plain sentences with common, easy-to-pronounce words
    (ideal for text-to-speech), no lists or headings.
- Keep the prompt configurable (already is, via
  `config :soundai, Soundai.Conversation` → `:system_prompt`).
- Tests: assert a new conversation starts with the system prompt (message role
  `:system`) and that it contains the STT-interpretation and short-sentence
  instructions.

No endpoint, client, or config-key changes.

## Acceptance criteria

- [x] Default system prompt tells the model to best-effort interpret STT noise

- [x] Default system prompt asks for short, simple, easy-to-pronounce sentences.
- [x] Existing `config :soundai, Soundai.Conversation` `:system_prompt` override
      still works.
- [x] Test covers the prompt content; existing conversation tests still pass.
