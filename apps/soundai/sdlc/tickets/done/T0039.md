----
title: Messages tool — the family answering machine (save + play pending messages)
----

Two new LLM tools that turn Soundai into a shared family answering machine:
one saves a spoken message for another person, the other reads out the
pending messages and marks them played. Communal and best-effort by design:
names are free text extracted from speech, there is no authentication, and
anyone may hear anything — the 90s contestador, deliberately.

Target utterances:

```text
"Mensaje para Diego: no te olvides de tomar agua hoy"
"¿Tengo algún mensaje?"
"Dime el mensaje de Diego"
"Soy Diego, ¿tengo algún mensaje?"
```

## Design decisions

- **Relay, not bypass**: branched_llm injects tool results into the context and
  the LLM produces the final reply, so true zero-LLM playback would require
  surgery on the reply path. Instead both tools return ready-to-speak Spanish
  text (same trick as the Weather summaries) and their descriptions instruct
  the assistant to repeat the result verbatim. The LLM becomes a dumb relay;
  the reply still flows through SpeechText.clean + TTS unchanged.
- **Communal playback**: with no filters, get_messages plays *all* pending
  messages (press play on the tape). Names are optional filters the LLM fills
  only when the user names someone.
- **Delivery = timestamp, not delete**: playing marks `delivered_at`; rows are
  kept forever (family archive). Unplayed only.
- **Sender unknown is normal**: "Mensaje para Diego: …" says nothing about who
  speaks; `from` is omitted and stored as NULL, spoken as "alguien".
- **Best-effort matching**: names match after trimming, downcasing and
  stripping accents ("MAMÁ" ≈ "mamá"); original text is stored verbatim.
  Misses ("Pepe" vs "José") are accepted chaos.
- **Bounded playback**: at most 5 messages per call (config `:max_played`),
  oldest first, with a "…y queda(n) N mensaje(s) más." tail when more remain;
  only the played ones are marked delivered.
- **Caps at save time**: body ≤ 500 bytes, names ≤ 100 bytes; blank names are
  stored as NULL. Validation lives in the changeset; tool callbacks translate
  failures into short English error strings for the LLM to phrase.
- **The system prompt stays untouched** — behavioral guidance rides in the
  tool descriptions (existing convention).
- **Callbacks never raise**: DB failures are caught and returned as
  `{:error, reason}` so the LLM apologizes gracefully (Weather pattern).

## Implementation

- Migration `create_messages`: `body :text null: false`, `from_name :string`,
  `to_name :string`, `delivered_at :utc_datetime`, timestamps; no extra
  indexes (family scale).
- `Soundai.Messages.Message` (schema): cast body/from_name/to_name, require
  body, trim body, trim-to-nil names, byte-length caps.
- `Soundai.Messages` (context, mirrors `Soundai.Notes`, public-by-design
  credo note): `save_message/1`, `pending_messages/0\\1` (opts `:from`/`:to`,
  Elixir-side normalized filtering, oldest first), `mark_delivered/1`.
- `Soundai.Conversation.Tools.SaveMessage` — `save_message(to, body, from?)`;
  confirmation "Mensaje guardado para X." / "Mensaje guardado."
- `Soundai.Conversation.Tools.GetMessages` — `get_messages(to?, from?)`;
  formats "Tienes N mensaje(s) nuevo(s): de X: …", marks played ones delivered.
- Config: register both in `config :soundai, Soundai.Conversation, :llm_tools`
  (`config/config.exs`).

## Tests

- `test/soundai/messages_test.exs` (DataCase): save/pending roundtrip, trims
  and nil-ing of names, blank/oversized rejections, delivered exclusion,
  ordering, case/accent-insensitive `:from`/`:to` filters, combined filters,
  mark_delivered stamps and empties pending.
- `test/soundai/conversation/tools/save_message_test.exs`: confirmation text,
  persistence, missing/blank recipient or body → `{:error, …}`, oversize body.
- `test/soundai/conversation/tools/get_messages_test.exs`: empty phrasing
  (with and without names), single/plural scripts, "alguien" for unknown
  sender, filters, >5 backlog tail, delivery side effect.

## Done

- `priv/repo/migrations/20260824145017_create_messages.exs`: `messages` table
  (body text not null, from_name/to_name strings, delivered_at utc_datetime,
  timestamps). No extra indexes — family scale.
- `lib/soundai/messages/message.ex`: schema with manual `@type t` (Ecto does
  not generate it); changeset requires body (≤ 500 bytes), trims it, and
  trim-to-nils both names (≤ 100 bytes) so blanks store as NULL.
- `lib/soundai/messages.ex`: context mirroring `Soundai.Notes` (public-by-
  design credo note): `save_message/1`, `pending_messages/0\\1` (oldest
  first; Elixir-side filtering so names match downcased and accent-stripped;
  unknown senders never match a named `:from`, recipient-less messages pass
  every `:to`), `mark_delivered/1` (stamps now, keeps rows).
- `lib/soundai/conversation/tools/save_message.ex`: `save_message(to, body,
  from?)` tool; blank args rejected as "missing …", oversized names caught
  before the DB, confirmation "Mensaje guardado para X." / "Mensaje guardado.";
  never raises on changeset/constraint failures.
- `lib/soundai/conversation/tools/get_messages.ex`: `get_messages(to?, from?)`
  tool; blank filter strings mean absent; plays at most 5 oldest pending with
  a "Queda(n) N mensaje(s) más" tail and marks only those delivered (best-
  effort rescue); scripts like "Tienes un mensaje nuevo. De X: …" with
  "de alguien" for unknown senders; DB failures return `{:error, reason}`.
- `config/config.exs`: both tools appended to `:llm_tools`.
- Tests: `messages_test.exs` (16), `save_message_test.exs` (8),
  `get_messages_test.exs` (9) — matching semantics, caps, delivery side
  effects, backlog tail.
- Docs: TECHNICAL_DESCRIPTION §1.3 tools paragraph + repository layout updated.
