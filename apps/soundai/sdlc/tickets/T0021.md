----
title: TTS pipeline robustness — bounded timeouts, failure caching, error normalization
----

The `Soundai.TTS` → `OrtexServer` chain has several paths where a caller can
hang forever, crash instead of getting `{:error, reason}`, or trigger
expensive retry storms. The documented contract everywhere is "return
`{:ok, wav}` or `{:error, reason}`"; this ticket makes the code honor it.

## Scope

### 1. Bounded call timeout + exit normalization (`tts/ortex_server.ex:31`)

`GenServer.call(pid, {:synthesize, text}, :infinity)` blocks callers forever
if inference hangs, and raises an uncaught exit in the caller if the server
dies mid-call. Wrap it:

- configurable bounded timeout (default ~120 s, e.g.
  `config :soundai, Soundai.TTS.OrtexServer, :synthesize_timeout_ms`);
- `try/catch :exit` → normalize to `{:error, {:tts_unavailable, reason}}`.

### 2. Cache failed model-load state (`ortex_server.ex:73-76`)

When the model is missing or fails to load, every subsequent synthesize
re-attempts ONNX session creation (expensive) and re-logs errors — a retry
storm under load. Store the failure in state (e.g. `model: {:failed, reason}`)
so calls fail fast; optionally allow one periodic re-probe (e.g. every 60 s)
or rely on a supervisor restart to clear it — pick one and document.

### 3. Catch-all in `ensure_model/1` (`ortex_server.ex:62`)

`load_model/1` rescues exceptions but `ensure_model/1` only matches
`{:ok, _}` / `{:error, _}`. An unexpected return shape from `Ortex.load`
raises `CaseClauseError` inside the server. Add a catch-all clause producing
`{:error, {:unexpected_load_result, term}}`.

### 4. Normalize adapter failures (`tts.ex:47-48`) and invalid UTF-8 (`tts.ex:56`)

- The adapter dispatch is not wrapped: a raising adapter (broken mock, ONNX
  runtime crash, model file deleted between `enabled?` and use) escapes as an
  exception → 500 instead of `{:error, reason}`. Wrap the `with` in
  `try/rescue`/`catch` and normalize.
- `is_binary(text)` matches binaries with invalid UTF-8;
  `String.trim/1` then raises `ArgumentError`. Add `String.valid?/1` to the
  guard (and in `validate_text/1`) so bad bytes map to `{:error, :invalid}`.

### 5. Log discarded error reasons (`soundai_web/controllers/tts_controller.ex:30-31`)

The fallback `{:error, _reason}` clause returns a generic 500 and drops the
reason (e.g. `{:inference_failed, msg}`), leaving production root causes
invisible. `Logger.error("TTS synthesis failed: #{inspect(reason)}")` while
keeping the generic response body (no internals leaked). While there, set
`Content-Length` explicitly for the WAV body instead of relying on implicit
framing.

## Tests

- Fake adapter that `raise`s → `Soundai.TTS.synthesize/2` returns
  `{:error, _}`, no exception escapes.
- Invalid UTF-8 binary input → `{:error, :invalid}` (no `ArgumentError`).
- OrtexServer started via `start_supervised!` with a nonexistent model path:
  repeated synthesize calls fail fast (assert state shows cached failure /
  second call does not attempt reload — e.g. count log events or inspect
  state via `:sys.get_state`).
- Simulate unexpected loader result (inject loader fun or test the private
  clause via a stubbed module) → `{:error, _}`, no CaseClauseError.
- Caller-side exit: kill the server process between `whereis` and call (or
  use a stub server that exits) → client gets `{:error, _}` within the
  timeout, does not hang or crash.
- Controller: error path still returns generic JSON but emits the
  `Logger.error` line (capture logs with
  `@moduletag :capture_log` / `ExUnit.CaptureLog`).

## Acceptance criteria

- [ ] No caller of `Soundai.TTS.synthesize/2` can hang indefinitely or receive
      an exception; contract holds for all inputs.
- [ ] Failed/missing model loads are cached and fail fast.
- [ ] TTS controller logs root-cause reasons server-side.
