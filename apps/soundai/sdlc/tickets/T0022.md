----
title: WAV encoder correctness — shape guards, input validation, full-range quantization
----

`Soundai.TTS.Wav` silently accepts shapes/values it cannot represent
correctly, which can corrupt audio instead of failing loudly.

## Scope

### 1. Restrict the reshape fallback (`wav.ex:21-24`)

The fallback clause flattens *any* non-`{1, n}` tensor to mono — a `{2, n}`
stereo tensor would be linearized into garbled audio with no warning.
Restrict to what `@doc` promises (rank-1 or `{1, n}`): check `Nx.rank/1` /
`Nx.shape/1` and raise `ArgumentError` on anything else.

### 2. Validate list input (`wav.ex:26-28`)

The list clause assumes flat numeric samples; a string/atom/nested list
raises deep inside `max/min/round` with an unhelpful
`Protocol.UndefinedError`. Validate `Enum.all?(samples, &is_number/1)` first
and raise a descriptive `ArgumentError`; document the expected flat numeric
list (range [-1.0, 1.0]) in `@spec`/`@doc`.

### 3. Full-range quantization (`wav.ex:33-34`)

Multiplying by 32767 never produces -32768 (slight range underuse). Multiply
by 32768 and clamp to `-32768..32767` so ±full-scale maps to the extremes
consistently (keep clamping — 1.0 × 32768 must clamp to 32767). Note in a
comment why 32768 + clamp (banker's rounding from `round/1` stays acceptable;
pin behavior in tests either way).

## Tests

- Real clamped-byte assertions replacing the weak ones:
  `{wav, _} = Wav.encode([2.0, -2.0])` → data equals
  `<<32_767::signed-little-16, -32_768::signed-little-16>>` (per chosen
  scheme); `[1.0]`, `[0.0]`, `[-1.0]` boundary values pinned exactly.
- Fix the tautological header assertions:
  `assert h.data_size == 2 * n_samples` and
  `assert byte_size(wav) == 44 + h.data_size` against known payloads (the old
  `h.data_size == byte_size(h.data)` can never fail).
- `{2, n}` tensor → raises `ArgumentError` (test via
  `assert_raise`).
- Non-numeric / nested-list input → raises descriptive `ArgumentError`.
- Round-trip sanity on real synth output stays green
  (`OrtexServer` tests from T0021 cover integration).

## Acceptance criteria

- [ ] Only documented shapes/inputs are accepted; everything else fails
      loudly with a clear message.
- [ ] Quantization uses the full int16 range deterministically.
- [ ] No tautological assertions remain in `wav_test.exs`.
