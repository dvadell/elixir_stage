----
title: Test suite isolation — global app-env leaks & async:false contracts
----

Several test modules mutate global `Application` env and only partially
restore it, making the suite order-dependent; one moduledoc describes sandbox
behavior that doesn't exist.

## Scope

### 1. `test/support/conn_case.ex:6-7` (high)

The moduledoc claims SQL sandbox checkout/revert that is not implemented (no
`Ecto.SQL.Sandbox` anywhere; `test_helper.exs` only starts ExUnit). Fix the
documentation to describe what actually happens (conn building only); add
sandbox setup only if DB tests are actually coming — otherwise delete the
claim.

### 2. `test/soundai/conversation_test.exs:12-15` (high)

`setup` writes only `adapter` + `fake_capture_pid`, but tests set
`fake_error`, `fake_response`, `max_response_chars`, `system_prompt`,
`llm_tools` which are never cleared — state set by one test leaks into later
ones (currently masked by execution order). Reset **every** fake knob in
`setup` (`Application.put_env` defaults / `delete_env` for test-only keys)
with the existing `on_exit` restore kept as backstop. Verify with random
seeds until confident.

### 3. `test/soundai_web/controllers/transcription_controller_test.exs:8-13`

Same treatment as (2): full per-test env reset instead of relying on
snapshot-at-setup + `on_exit`.

### 4. Document `async: false` contracts

`tts_test.exs`, `weather_test.exs`, `tts_controller_test.exs` are safe only
while `async: false` because they mutate shared app env. Add a one-line
comment at each `use` statement stating the constraint so a future
`async: true` flip doesn't introduce nondeterministic races silently.

## Tests

This ticket *is* tests; acceptance verification:

- Run `mix test` with several explicit seeds
  (`mix test --seed 123456`, a few more) and with
  `--repeat-until-failure 10` on the affected files — all green regardless
  of order.
- Intentionally break one knob reset locally to confirm the suite now fails
  instead of passing by luck.

- [ ] conn_case docs match reality.
