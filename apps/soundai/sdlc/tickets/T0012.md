----
title: Add branched_llm dependency + NVIDIA provider configuration
----

Make `branched_llm` (the LLM conversation manager) available to `soundai` and
configure it to talk to the NVIDIA OpenAI-compatible endpoint. This is
infrastructure for the whole epic; no behavior change yet — the server still
echoes until T0013.

## Prerequisites

- branched_llm enhancements BL-01…BL-03 implemented and pushed to
  `dvadell/branched_llm` as a git tag (e.g. `v0.3.0`). The dep must reference
  that tag so `mix deps.get` pulls the fixed/supervised version.

## Scope

### 1. Dependency

- Add to `apps/soundai/mix.exs`:

  ```elixir
  {:branched_llm, github: "dvadell/branched_llm", tag: "v0.3.0"}
  ```

  (adjust tag to whatever BL work ships as). `branched_llm` brings `req_llm`,
  `jason`, `retry`, `telemetry` (and optional `ecto`/`opentelemetry_api` — do
  not enable those for now).
- Run `mix deps.get` from the umbrella root and resolve any version conflicts
  with the existing `req`, `jason`, `phoenix*` deps. Commit the `mix.lock`
  update.

### 2. Config (umbrella `config/config.exs` + `config/runtime.exs`)

- Add a `config :branched_llm` block in `config/config.exs`:

  ```elixir
  config :branched_llm,
    ai_model: System.get_env("LLM_MODEL") || "nvidia:openai/gpt-oss-20b",
    default_provider: :nvidia,
    max_tokens: 128_000

  config :branched_llm, :providers,
    nvidia: [
      base_url: "https://integrate.api.nvidia.com/v1",
      api_key: {:system, "NVIDIA_API_KEY"}
    ]
  ```

  - `NVIDIA_API_KEY` is already exported; keep reading it from the env at
    runtime (do not hard-code the key).
  - `openai/gpt-oss-20b` is the default model (verified reachable on this
    account; several other NVIDIA-hosted models time out or 404).
- In `config/runtime.exs`, allow overrides: `LLM_MODEL`, `LLM_BASE_URL`,
  `NVIDIA_API_KEY`. Follow the existing `SOUNDAI_TTS_MODEL_PATH` style.

### 3. Boot integration

- After BL-02, `branched_llm` ships its own Application that supervises the
  `ChatOrchestrator.TaskSupervisor`; confirm it is started automatically as a
  dependency of `soundai` (check the supervision tree in `iex`).
- If BL-02 is not merged yet, note the gap in a comment: the ad-hoc
  `ensure_started` supervisor is linked to the caller and must not be relied on.

### 4. Smoke test

- Add a small `mix soundai.llm_smoke` task (or a `Logger`-heavy `iex -S mix`
  check) that builds a context, calls `BranchedLLM.Chat.send_message/3` with a
  Spanish prompt, and prints the response. It must not be part of the test
  suite (live network); guard it so `mix precommit` never runs it.

## Implementation notes

- Dep pinned to `dvadell/branched_llm` **tag `v0.3.1`** (not `v0.3.0`):
  `v0.3.0` carried a `Code.ensure_loaded?(OpenTelemetry.Tracer)` +
  `require` block that Elixir 1.18+ processes unconditionally, so it failed to
  compile in any consumer without `opentelemetry_api`. `v0.3.1` drops the
  optional span wrapper (telemetry events kept) and an unused `require Logger`.
- **Provider is `:openai`, not `:nvidia`** — req_llm 1.17.1 has no `:nvidia`
  provider. The NVIDIA OpenAI-compatible endpoint is reached through the
  `:openai` provider with a custom `base_url`:
  `config :branched_llm, ai_model: "openai:openai/gpt-oss-20b"`,
  `default_provider: :openai`, plus per-provider `base_url` and
  `api_key: {:system, "NVIDIA_API_KEY"}`. The ticket's `nvidia:openai/...`
  string was not viable.
- `config/config.exs` + `config/runtime.exs` allow `LLM_MODEL`, `LLM_BASE_URL`,
  `NVIDIA_API_KEY` overrides (SOUNDAI_TTS_MODEL_PATH style).
- `mix soundai.llm_smoke` task added (`apps/soundai/lib/soundai/mix/tasks/`);
  builds a context, sends a Spanish prompt via `Chat.send_message/3`, prints the
  response. Live network — never runs under `mix test`/precommit.
- Root `mix.exs` gained `dialyzer: [plt_add_apps: [:mix, :ex_unit]]` so dialyzer
  can analyze the Mix task (was: `callback_info_missing` /
  `unknown_function Mix.Task.run/1`).
- Note: the shell currently exports `LLM_MODEL=openai:z-ai/glm-5.1`, which is
  **dead** on NVIDIA (HTTP 410, EOL 2026-07-02). The config fallback
  `openai:openai/gpt-oss-20b` only applies when `LLM_MODEL` is unset; unset it
  (or point it at a live model) before running the server.
