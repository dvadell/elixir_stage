----
title: Honest model & language reporting across the TTS API
----

The public TTS surface lies about what it did: `Soundai.TTS.synthesize/2`
accepts a `language` argument it ignores (`tts.ex:46`), and both controllers
hardcode `X-TTS-Model: Xenova/mms-tts-spa` regardless of the configured
model (`tts_controller.ex:21`, `conversation_audio_controller.ex:101`). If
the deployed model changes via `SOUNDAI_TTS_MODEL_PATH` / `:model_path`, or a
non-Spanish language is requested, clients get misleading metadata.

## Scope

1. **Language parameter** — pick one and document:
   - validate against the supported set (currently Spanish-only) and reject
     others with `{:error, :unsupported_language}` → 422, or
   - wire it through to adapter/model selection.
   The current deployment is Spanish-only; rejecting is the honest minimal
   fix. Keep the param in the API so wiring later is non-breaking.

2. **Model reporting** — return the actual model identity from the synthesis
   envelope:
   - Add an explicit `:model_name` to the TTS config (default
     `"Xenova/mms-tts-spa"`) or derive it once from `model_path`;
   - `Soundai.TTS.synthesize/2` success tuple includes it;
   - both controllers set `X-TTS-Model` (and the audio endpoint's
     `x-tts-model`) from that value instead of the hardcoded string.

3. **Docs** — TECH_DESCRIPTION routes/response tables updated for the 422 and
   header semantics.

## Tests

- Unsupported language (`"klingon"`) on `/api/tts` → 422 with stable error
  body (and same policy honored by `/api/conversations/audio`).
- Override `config :soundai, Soundai.TTS, model_name/model_path` → header
  reflects the override in both endpoints.
- Default config keeps today's behavior (`Xenova/mms-tts-spa`) so existing
  client fallback logic is unaffected.

## Acceptance criteria

- [ ] No request can silently synthesize with a different language than
      requested.
- [ ] `X-TTS-Model` always reports the model actually used.
- [ ] Behavior documented; existing tests updated where they pinned the
      hardcoded header.
