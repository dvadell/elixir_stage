----
title: Benchmark local TTS and evaluate Supertonic-TTS-2
----

Follow-up to T0007: **benchmark the local TTS engine** (`Xenova/mms-tts-spa`)
that now ships, and **evaluate `onnx-community/Supertonic-TTS-2-ONNX`** — the
higher-quality, multilingual option already listed (but non-functional) in the
`/settings` picker. If Supertonic passes the evaluation, enable it in
`TTS_CONFIG` and `@tts_models`; if not, remove it from the list.

This ticket has **no required code change**; it is research that ends in a
decision. The engine architecture from T0006/T0007 means enabling a new model is
a config-only change.

## Scope

### 1. Benchmark `Xenova/mms-tts-spa` (already shipped)

Reproduce the T0003 benchmark methodology for TTS, per target environment:

| Environment | Expected device |
|-------------|-----------------|
| Chrome (WebGPU) | `webgpu` |
| Chrome + WebGPU disabled (`--disable-features=WebGPU`) | `wasm` |
| Firefox (WASM) | `wasm` |

Metrics to collect (same fixed Spanish response text, 3-run median):

1. **First model load time** — `init` started → `ready` (download + compile),
   cold vs cached.
2. **Primed synthesis latency** — text sent → `audio` result (worker) and →
   audible start (playback).
3. **Synthesis ratio** — synthesized audio duration / wall-clock synthesis time
   (is it real-time or faster?).
4. **Memory footprint** — DevTools heap/JS memory delta after load and after
   synthesis.
5. **Download sizes** — quantized (q8/WASM) vs fp16 (WebGPU) for the selected
   model; report the exact bytes.

Report cached vs cold, and WebGPU vs WASM, in the ticket's final status.

### 2. Evaluate `onnx-community/Supertonic-TTS-2-ONNX`

- Model card facts to verify (from research at ticket creation):
  - `pipeline_tag: text-to-speech`, `transformers.js` library — the pipeline id
    is compatible with the existing `pipeline("text-to-speech", ...)` call.
  - Files: `onnx/text_encoder.onnx` (+`_data`), `onnx/latent_denoiser.onnx`
    (+`_data`), `onnx/voice_decoder.onnx` (+`_data`) — total ~260 MB.
  - Spanish is supported (multilingual). Verify with a real utterance.
- Checklist:
  - [ ] Loads in the current installed `@huggingface/transformers` version
        (the repo pins `^4.2.0`; confirm Supertonic does not need a newer one).
  - [ ] The `text-to-speech` pipeline returns a playable `Float32Array` +
        `sampling_rate` with the existing `transformers` engine, without
        engine-specific code.
  - [ ] Spanish quality is meaningfully better than `mms-tts-spa` (subjective,
        but capture a comparison on the same sentences).
  - [ ] First load time, primed synthesis latency, and memory fit the target
        users' devices (older adults, possibly low-end hardware).
  - [ ] Runs on both `webgpu` and `wasm` (or at least `wasm`, with fallback
        working).
- If **any** check fails on the reference browser/device, **remove** the
  Supertonic option from `TTS_CONFIG.models` and `SettingsHTML @tts_models` and
  record why. If it passes, enable it.

### 3. Act on the result (decision gate)

- **Pass → enable**: add `onnx-community/Supertonic-TTS-2-ONNX` to
  `TTS_CONFIG.models` (with per-device `dtype`) and keep its entry in
  `SettingsHTML @tts_models` (already present from T0006). Ensure the
  description in `data-desc` mentions the larger download.
- **Fail → remove**: delete the option from `@tts_models` and `TTS_CONFIG`.
  Optionally record the reason in a comment so it can be revisited later.
- Either way, confirm the default engine stays `Xenova/mms-tts-spa` unless the
  benchmark clearly favors Supertonic for the target audience.

### 4. Documentation

- Update `apps/soundai/sdlc/TECHNICAL_DESCRIPTION.md` with a short **TTS
  benchmarks** section (model, dtypes, devices, cached/cold numbers, memory) so
  the decisions are reproducible, mirroring the STT benchmark notes.
- If Supertonic is removed, note that in the same section.
