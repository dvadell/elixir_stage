----
title: Security hardening quick wins (salt, RequestLogger, cookie flags, key redaction)
----

Small, concrete security fixes that don't need the T0019 spike and can land
immediately.

## Scope

### 1. Signing salt out of source code (`soundai_web/endpoint.ex:10`)

`signing_salt: "RxqfOFJ4"` is committed to the repo. Session cookies are
signed (not encrypted), so anyone with the salt can forge valid session
cookies. Move the value to config:

- `config/config.exs`: read from env with a dev fallback;
  `config/runtime.exs` (or `test.exs`) supplies the real value per
  environment, e.g. `System.get_env("SOUNDAI_SIGNING_SALT") || ...`.
- Document salt rotation (invalidates existing sessions — acceptable here).

### 2. Gate LiveDashboard RequestLogger in production (`endpoint.ex:40-42`)

The `Phoenix.LiveDashboard.RequestLogger` plug runs unconditionally, so in
prod anyone setting the `request_logger` query param/cookie can stream recent
request logs (URLs, status, timing — potentially sensitive). Only enable it
when code reloading/dev is on:

```elixir
if code_reloading? do
  plug Phoenix.LiveDashboard.RequestLogger, ...
end
```

(or gate on an explicit config flag if the dashboard is ever wanted in prod
behind auth).

### 3. Cookie flags

- `soundai_conversation` cookie (`transcription_controller.ex`): set
  `secure: true` when serving over HTTPS (derive from endpoint config or a
  config flag so plain-http dev keeps working) and confirm `http_only: true`.
- `assets/js/settings.js` `writeCookie`: append `; Secure` when
  `location.protocol === "https:"`.

### 4. Redact credentials in the smoke task (`mix/tasks/soundai.llm_smoke.ex`)

- `inspect(reason)` on the error path can embed HTTP request details including
  the `Authorization: Bearer <NVIDIA_API_KEY>` header → credential leaked to
  console/logs. Sanitize before printing: strip/drop `:headers`, `:request`,
  and any values containing the configured key; print only the exception
  class/message.
- Also pass a bounded `timeout:` (read `:llm_timeout_ms`, default 30_000) to
  `BranchedLLM.Chat.send_message/3` so a provider hang fails fast instead of
  blocking the terminal forever.

## Tests

- Endpoint/session: test that `@session_options` signing salt comes from
  config (assert `Application.get_env` path used; e.g. compile-time assert or
  a small unit test on the options builder if extracted).
- RequestLogger: in a prod-config simulation (`code_reloading? == false`),
  assert the plug is not in the endpoint pipeline (inspect `@plugs` /
  behavioral check that `?request_logger=` is ignored).
- Cookies: conn test asserting `secure`/`http_only` attrs on the
  Set-Cookie header when the secure flag config is on.
- Smoke task: pure-function test for the sanitizer — feed it an error struct
  containing a fake header list with a secret, assert secret absent from
  output; timeout option passed through (capture via fake adapter opts).

## Acceptance criteria

- [ ] No secret material in source; app boots in dev/test/prod with
      configured salts.
- [ ] RequestLogger inactive outside dev.
- [ ] Conversation + settings cookies carry Secure on HTTPS deployments.
- [ ] Smoke task never prints the API key and cannot hang indefinitely.

## Verification

```sh
cd apps/soundai && mix test && mix precommit   # umbrella root
grep -R "RxqfOFJ4" apps/soundai --exclude-dir=done || true   # expect no hits
```

Manual: run `mix run -m mix soundai.llm_smoke` with a bad `NVIDIA_API_KEY`
and confirm the printed error contains no `Authorization`/key material.
