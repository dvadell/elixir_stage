title: Vendor topbar.js — defensive patches for NaN / null-canvas / timer leaks

The vendored loading bar (`assets/vendor/topbar.js`) has several crash/stuck-
state paths. It's vendor code, so patches stay minimal and are documented
in-file so a future regeneration doesn't silently drop them.

## Scope

Add a header comment block ("Local modifications:") listing each deviation,
then:

1. **Null canvas context (line 39)**: `canvas.getContext('2d')` can return
   null → immediate TypeError breaks the page. Guard and bail out.
2. **NaN progress (lines 97-100)**: `topbar.progress('abc')` → `parseFloat`
   NaN corrupts state and later `lineTo(NaN)` throws a DOMException
   permanently. Guard: `if (isNaN(to)) return currentProgress`.
3. **Deferred-show timer leak (line 75)**: reset `delayTimerId = null` inside
   the timeout callback, else a second delayed `show(200)` is dropped.
4. **Fade-out opacity NaN (line 117)**: `canvas.style.opacity -= 0.05` yields
   NaN if opacity starts as `''`; decrement via `parseFloat(...)` so the fade
   always completes.
5. **Resize listener persistence (line 64, optional)**: expose `destroy()`
   removing the listener + canvas element (only if trivially safe; otherwise
   document as accepted).

## Tests

Manual smoke (topbar shows briefly during LV navigation/push events):

- Call `topbar.progress('abc')` then `repaint` — no exception, bar unchanged.
- `topbar.show(200)` twice back-to-back — bar appears both times.
- Force `opacity` manipulation then hide — bar fully disappears (no stuck
  overlay).
- Window resize repeatedly while shown — no errors, repaint OK.
